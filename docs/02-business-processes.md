## 2. 前置主檔建立與核准流程

詢價、老闆核價及客戶確認在系統外完成；系統保存已確認的料號對應與客戶價格。下列主檔完成核准或覆核並啟用後，才可供後續 SO、PO 與應收流程使用。這些是交易前置作業，不代表每張訂單都要重新建立。

| 主檔或條件 | 建立或申請 | 覆核或核准 | 生效後用途 |
| --- | --- | --- | --- |
| 客戶基本資料 | 業務 | 業務主管 | 啟用後可建立 SO；新客戶預設採現結 |
| 付款條件 | 財務主管直接設定 | 不另設核准 | 新客戶預設現結；財務主管可改為 30 天或 60 天並留下異動紀錄 |
| 公司料號 | 業務 | 業務主管 | 啟用後可建立客戶料號對應及交易資料 |
| 客戶料號及公司料號對應 | 業務 | 業務主管 | 啟用後，輸入客戶料號可查用對應的公司料號 |
| 客戶價格 | 業務 | 業務主管 | 保存未稅 TWD 單價及計價單位；核准後立即啟用並取代舊版本；SO 草稿可暫缺價格，但送審須引用 `ACTIVE` 價格 |
| 供應商資料 | 採購 | 採購主管 | 核准後可成為正式採購來源 |

同一人可兼任多個角色，但核准者不得是目標資料的建立者，也不得是該輪申請的送審者；實際替代核准與授權原則詳見 [角色與權限規格](04-roles-and-permissions.md)。

## 4. 缺料與補貨子流程 (圖2)

此圖同時呈現由 SO 缺料建立的關聯 PO，以及不綁定 SO 的一般補庫 PO。只有關聯 PO 的合格入庫量會依來源關係預留給特定 SO。

    subgraph PURCHASING[採購]
        RELATED_PO[建立關聯 PO 草稿<br/>已規劃、未下單]

        PO_RETURN[依退回原因修改]
        PO_ORDER[產生 PO PDF<br/>並向供應商下單]
    end

    subgraph PURCHASING_MANAGER[採購主管]
        PO_REVIEW{核准 PO？}
    end

    subgraph WAREHOUSE[倉管]
        RECEIVE[依 PO 驗收到貨<br/>記錄合格與異常數量]
    end

    SO_SHORTAGE --> PLAN_QTY --> RELATED_PO --> PO_REVIEW
    GENERAL_NEED --> GENERAL_PO --> PO_REVIEW
    PO_REVIEW -- 退回 --> PO_RETURN --> PO_REVIEW
    PO_REVIEW -- 核准 --> PO_ORDER --> RECEIVE --> SOURCE

本採購子流程在「到貨驗收與入庫」完成供應及庫存交接；供應商請款、應付帳款、付款申請與付款核銷不在本次專題交付範圍。

## 5. 端到端步驟對照表

| 步驟 | 主要角色 | 工作與系統結果 |
| --- | --- | --- |
| 1 | 業務 | 收到客戶正式訂單後，透過 Web 或 LINE AI 建立 SO 草稿。LINE AI 每次解析一則完整輸入；資料缺漏或有歧義時列出問題，業務重新送出完整描述。解析成功後須由原發起者確認預覽，系統才建立草稿。 |
| 2 | 業務／系統 | 系統依客戶料號對應帶入公司料號、`ACTIVE` 客戶價格、付款條件及單位換算；業務輸入數量、要求交貨日、交貨方式、地點等本次交易資料，確認後送審。送審時，系統確認客戶、公司料號、料號對應及價格來源仍可使用，檢查必要資料是否完整，並保存本次交易採用的價格、付款及交貨條件。若沒有 `ACTIVE` 價格，草稿可保存但不得送審。 |
| 3 | 業務主管／系統 | 業務主管核准 SO 後，系統依當下可用庫存預留可供貨數量。SO 詳細頁依品項顯示已預留、已規劃未下單、採購在途及尚待規劃供應的數量。預留不改變可出貨實體數量，只使相同數量不再供其他 SO 使用。 |
| 4 | 採購／採購主管 | 缺料時，採購可針對尚待規劃供應的數量建立關聯 PO 草稿，也可依安全庫存警示或實際需求建立一般補庫 PO。採購主管核准後，採購產生正式 PO PDF 並向供應商下單，未到貨的數量從此時起才列為採購在途。 |
| 5 | 倉管／系統 | 供應商到貨後，倉管依 PO 驗收，記錄合格、損壞與規格不符數量。只有合格數量增加可出貨實體庫存；關聯 PO 的合格數量在來源 SO 仍有需求時預留給該 SO，一般補庫的合格數量及超出來源需求的部分成為一般可用庫存。異常數量只保留於驗收紀錄，不計入庫存。 |
| 6 | 業務／系統 | 業務依客戶需求確認本次預計出貨品項、數量、預計出貨日、地點及特殊需求並通知出貨。原則上以剩餘有效數量整批出貨；客戶明確急需時，可選擇部分品項或數量分批出貨。系統確認本次選定數量均已預留後，才建立 DO 草稿。 |
| 7 | 倉管 | 倉管在 DO 頁面產生揀貨單並完成揀貨、核對與包裝，只查看履約所需資料，不取得完整售價等非必要銷售資訊。倉管於完成揀貨時確認實際出貨量；實際量不得大於 DO 預計量。 |
| 8 | 倉管／系統 | 系統依實際出貨量產生有正式編號的出貨單 PDF，DO 轉為 `READY`。少於預計量的差額不使用預留，仍保留於來源 SO。貨物與文件交付司機時，倉管執行出貨過帳；系統再次檢查數量後扣減可出貨實體庫存、使用相應預留，DO 轉為 `POSTED`，並保存實際出貨日、操作時間及帳號。 |
| 9 | 系統 | DO 過帳後，系統自動產生應收草稿，每張 DO 產生一筆。金額依實際出貨量、SO 保存的未稅成交單價及固定 5% 營業稅計算，到期日依付款條件計算。 |
| 10 | 財務 | 財務核對 DO、含稅金額與外部發票資料，填入外部發票號碼及日期後確認正式應收。 |
| 11 | 財務／系統 | 財務登錄部分或全額收款，每次收款不得超過未收餘額。系統更新未收、即將到期及逾期資料；未收餘額歸零時完成應收結清。 |
| 持續更新 | 管理者／系統 | SO、PO、庫存、DO、應收與收款等資料建立或狀態異動後，系統可依固定規則即時計算接單、營收、缺貨風險、交易降溫及應收指標；營收以已過帳 DO 的實際出貨未稅金額計算。管理者可隨時透過儀表板與具有來源依據的 AI 摘要判斷後續處理順序，不必等待整張 SO 履約結案或應收結清。 |

## 6. 核心控制與例外流程

### 6.1 核心控制原則

- SO 核准前不預留庫存，也不能由 SO 建立關聯 PO 或建立 DO。
- PO 草稿與待核准 PO 只代表需求已有規劃；PO 核准並向供應商下單後，尚未合格入庫的數量才是採購在途。
- DO 只能使用已預留給來源 SO 的數量。
- 產生正式出貨單 PDF 不代表實際出庫；倉管將貨物與文件交付司機並執行過帳時才扣減庫存。
- 同一張 DO 不得重複過帳，也不得重複產生應收。
- 同一 SO 明細所有未過帳、未作廢 DO 數量加總不得超過有效預留；建立或修改 DO 及過帳時都要重新檢查。
- SO 的有效數量全部出貨過帳後即可履約結案；應收是否收清不影響 SO 的履約狀態。
- 每張已過帳 DO 對應一筆應收；正式應收可分次收款，未收餘額歸零時才完成應收結清。
- 一般補庫合格入庫、其他 SO 釋放預留或庫存調增所增加的可用庫存，不自動改配給既有缺料 SO。

### 6.2 例外流程

| 例外情況 | 處理方式 | 系統結果 |
| --- | --- | --- |
| 客戶取消部分未出貨數量 | 業務提出餘量取消申請，由業務主管核准 | 取消尚未出貨的有效數量並釋放相應預留；其餘有效數量全部出貨後，SO 仍可履約結案 |
| SO 取消或減量時已有關聯 PO | 不自動取消已送出的 PO，由採購依實際狀況續辦或另外處理 | 後續合格到貨若已無來源 SO 需求，轉為一般可用庫存 |
| 已核准 PO 尚未收貨而取消 | 採購主管直接取消並填寫原因 | PO 與正式 PDF 標記取消／作廢，未到貨量移出採購在途；未被補足的來源 SO 數量重新成為尚待規劃供應量 |
| PO 部分收貨後短收結案 | 採購主管直接結案並填寫原因 | 已入庫部分不變，未到貨餘量轉為取消量；未被補足的來源 SO 數量重新成為尚待規劃供應量 |
| 到貨損壞或規格不符 | 倉管依實際驗收結果分別記錄合格、損壞及規格不符數量，並記錄異常原因 | 只有合格數量增加可出貨實體庫存；異常數量保留於驗收紀錄，不列入庫存，由採購與供應商確認補貨或短收結案 |
| 已過帳收貨登錄錯誤 | 本次專題不提供過帳後更正；收貨過帳前須經確認畫面核對。不得以一般庫存調整假裝修正 PO 收貨資料 | 原收貨、PO 進度及庫存維持原紀錄；正式沖銷列為後續擴充，展示環境的錯誤測試資料重新建立 |
| 庫存調減超過可用庫存 | 系統拒絕操作並列出可能受影響的 SO；侵蝕預留的例外處理不納入本次專題交付 | 不改變實體庫存或預留，避免庫存調整破壞既有承諾 |
| 庫存調整登錄錯誤 | 倉管主管建立相反方向的新調整並關聯原調整 | 保留原始及更正紀錄；新調整仍須符合實體數量非負且不得侵蝕預留的限制 |
| `READY` 出貨單內容需更正 | 過帳前作廢原 DO 及正式 PDF，再依正確內容建立新 DO | 保留作廢原因、操作者與時間；每張 DO 只保存一份正式 PDF，不扣庫存或使用預留 |
| 正式應收的外部發票號碼或日期登錄錯誤 | 財務主管直接更正並填寫原因 | 應收狀態與金額不變；保存修改前後值、操作者及時間，並重新檢查發票號碼唯一性 |

單據狀態、庫存狀態與金額公式詳見 [領域與資料規則](05-domain-rules.md)。

## 7. 示範情境：SO_001

假設客戶與客戶料號對應已啟用，且財務主管已將客戶付款條件設定為 30 天。客戶訂購 PE 保溫管 10 支與 PU 管墊 5 個，其中 PU 管墊目前只有 2 個可用；客戶未要求急件，因此待缺料補齊後整單出貨。

1. **業務建單**：業務輸入客戶料號，確認系統帶出的公司料號、`ACTIVE` 未稅 TWD 價格及交易單位，完成 SO 草稿並送審。若沒有 `ACTIVE` 價格，草稿可保存但不得送審，須先完成價格建檔與覆核。
2. **主管核准與庫存預留**：業務主管核准後，系統預留 PE 保溫管 10 支與 PU 管墊 2 個，並顯示 PU 管墊尚有 3 個缺少供應來源。
3. **缺料採購**：採購以缺少的 3 個 PU 管墊建立關聯 PO 草稿。草稿只代表已規劃未下單；採購主管核准、產生 PO PDF 並向供應商下單後，3 個才列為採購在途。
4. **驗收入庫**：到貨後，倉管依 PO 記錄合格、損壞及規格不符數量。3 個合格品增加可出貨實體庫存，並依 PO 與 SO_001 的關係預留給該訂單；異常數量只保留於驗收紀錄，不列入庫存。
5. **建立 DO 與揀貨**：整張訂單的出貨數量均已預留後，業務確認本次出貨內容，由系統建立 DO 草稿；倉管產生揀貨單並完成揀貨、核對及包裝。
6. **出貨文件與過帳**：倉管確認實際出貨內容後產生正式出貨單 PDF，DO 轉為 `READY`。貨物及文件交付司機時執行出貨過帳，系統再次檢查數量、扣減可出貨實體庫存、使用相應預留，DO 轉為 `POSTED`，並保存實際出貨日與操作紀錄。由於有效訂購數量已全部出貨，SO 完成履約結案。
7. **產生及確認應收**：系統依實際出貨量、SO 保存的未稅成交單價及 5% 營業稅建立應收草稿。財務填入外部發票號碼並確認正式應收，到期日為實際出貨日加 30 日。
8. **收款與結清**：財務先登錄部分收款，系統保留未收餘額並持續判定到期或逾期；收到剩餘款項後再次登錄，未收餘額歸零，應收完成結清。
9. **營運分析**：主管可在儀表板查看淨接單、營收、未出貨訂單、缺貨風險、交易降溫及應收資料；AI 摘要使用同一組後端指標整理重要異常、可能原因、建議處理順序與來源連結。

LINE AI 可取代第 1 步的輸入方式，但不改變送審、核准及後續履約流程。
