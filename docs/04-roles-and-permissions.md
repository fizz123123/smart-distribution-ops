# 角色與權限規格

> 需求版本：v1.0  
> 建立日期：2026-09-29  
> 文件定位：定義系統角色、兼任原則、核准責任與資料查看邊界。

## 角色模型

角色是一組預設權限，使用者可以持有多個角色，也可被指派角色以外的個別權限。約 10 人的示範情境中，業務可兼任採購，業務主管也可兼任採購主管；未來改由專人負責時，只需重新指派角色與權限。

| 角色 | Role | 主要權限與責任 |
| --- | --- | --- |
| 業務 | `SALES` | 建立客戶、公司料號、客戶料號與 SO；申請帳期；查看自己負責 SO 的庫存、供應與缺料；釋出出貨；經本人 LINE 綁定與授權後使用 LINE AI |
| 業務主管 | `SALES_MANAGER` | 覆核公司料號、客戶料號與價格；核准客戶、SO 與未出貨餘量取消；查看業務部門銷售、客戶交易及 SO 缺料分析 |
| 採購 | `PURCHASING` | 建立供應商、關聯 PO 與一般補庫 PO；查看全部缺貨；核對供應商、數量、成本與交期；PO 核准後產生正式 PDF 並下單 |
| 採購主管 | `PURCHASING_MANAGER` | 查看全部缺貨與補貨進度；核准供應商與 PO；不得核准自己建立的資料 |
| 倉管 | `WAREHOUSE` | 查看履約所需庫存、預留、待入庫及備貨資訊；依 PO 驗收入庫；依 DO 揀貨、包裝、產生出貨單及執行交車過帳 |
| 倉管主管 | `WAREHOUSE_MANAGER` | 查看庫存與缺貨風險；處理隔離、解除隔離、庫存調整及倉儲例外 |
| 財務 | `FINANCE` | 核對應收草稿、填入外部發票資料並確認正式應收；登錄收款；追蹤未收、即將到期及逾期餘額 |
| 財務主管 | `FINANCE_MANAGER` | 核准或退回 `NET_30`、`NET_60` 付款條件；處理財務調整與收款例外 |
| 營運主管 | `MANAGER` | 查看全公司儀表板、缺貨風險及 AI 摘要；追查來源；在原核准人為申請者時，以相應權限替代核准客戶、SO、供應商、PO 或付款條件；處理 APP_ADMIN 本人帳號的授權異動 |
| 系統管理員 | `APP_ADMIN` | 管理其他使用者的帳號、角色與個別權限；查看、停用或解除 LINE 綁定；不得替使用者指定 LINE userId，也不得修改自己的角色或權限 |

APP_ADMIN 不因管理帳號而自動取得業務資料、交易或核准權限。

## 兼任與職務分離原則

- 同一使用者可持有多個角色，但建立者不得核准或覆核自己建立的資料。
- 任何人都不得建立、修改或刪除自己的角色及個別權限，即使同時持有 APP_ADMIN 或 MANAGER 也不例外。
- 原核准人親自提出申請時，資料改送具相應核准權限的 MANAGER。
- MANAGER 的替代核准限於客戶、SO、供應商、PO 及付款條件，不因此取得庫存調整或收款修改權限。
- MANAGER 的權限管理例外只用於處理 APP_ADMIN 本人帳號；不取代 APP_ADMIN 對一般帳號的管理責任。
- 所有建立、覆核、核准、退回、過帳、庫存調整、收款及授權異動均保存操作者、時間、結果與必要意見。

## 核准與生效矩陣

| 項目 | 建立或發起 | 覆核或核准 | 生效條件 |
| --- | --- | --- | --- |
| 客戶基本資料 | SALES | SALES_MANAGER 或具相應權限的 MANAGER | 核准後啟用；新客戶預設 `DUE_0` |
| 付款條件 | SALES 申請 | FINANCE_MANAGER 或具相應權限的 MANAGER | `NET_30`、`NET_60` 或既有帳期異動，核准後才可供新 SO 使用 |
| 公司料號、客戶料號及對應關係 | SALES | SALES_MANAGER | 待覆核、已啟用、退回；已啟用後可供 SO 查用 |
| 客戶價格 | SALES | SALES_MANAGER | 保存未稅 TWD 單價、計價單位、生效日與失效日；失效只顯示警示，不阻擋建立 SO item line |
| 銷售訂單 SO | SALES | SALES_MANAGER 或具相應權限的 MANAGER | 送審時保存交易快照；核准前不預留、不可建立關聯 PO、不可釋出出貨 |
| 供應商 | PURCHASING | PURCHASING_MANAGER 或具相應權限的 MANAGER | 核准後可成為正式採購來源 |
| 採購單 PO | PURCHASING | PURCHASING_MANAGER 或具相應權限的 MANAGER | 核准後才產生正式 PO PDF、向供應商下單並列入採購在途 |
| 出貨單 DO | SALES 釋出、系統建立 | 不另設主管核准 | SO 已核准，且本次出貨量均已預留；由 WAREHOUSE 執行履約與過帳 |
| 簡化應收 | 系統依已過帳 DO 建立 | FINANCE 確認 | 一張 DO 對一筆應收；外部發票資料填妥後轉為正式應收 |
| 未出貨餘量取消 | SALES | SALES_MANAGER | 核准後取消餘量並釋放預留 |
| 庫存例外 | WAREHOUSE | WAREHOUSE_MANAGER | 不直接改寫已完成的原始交易；以狀態異動或調整紀錄處理 |
| 財務例外 | FINANCE | FINANCE_MANAGER | 不直接改寫已完成的原始交易；保留例外原因與處理紀錄 |
| 角色與個別權限 | APP_ADMIN 或其他具授權管理權限者 | 不得由帳號本人處理 | 保存異動前後差異、操作者與時間 |

## 分析資料查看範圍

- MANAGER：全公司儀表板、AI 摘要與來源資料。
- PURCHASING、PURCHASING_MANAGER：全部缺貨、已規劃供應、採購在途及補貨進度；成本依採購權限顯示。
- WAREHOUSE、WAREHOUSE_MANAGER：庫存狀態、預留、待入庫、備貨及履約資訊；不因查看缺貨而取得非必要售價或採購成本。
- SALES_MANAGER：業務部門的銷售、客戶交易與 SO 缺料資料。
- SALES：自己負責 SO 的資料；資料歸屬依「負責業務」欄位，而不是建立者。
- FINANCE、FINANCE_MANAGER：應收、收款、到期與逾期資料；其他營運資料依另外授權顯示。
