# 領域與資料規則

> 需求版本：v1.0  
> 建立日期：2026-09-29  
> 文件定位：集中定義跨功能共用的名詞、狀態、公式與交易規則；本文件不等同資料庫設計。

## 核心名詞

- **負責業務**：SO 上獨立於建立者的業務歸屬。Web 建單預設為建立者；LINE 建單預設為完成綁定的系統帳號；主管代建時必須指定負責業務。
- **必要交貨資料**：要求交貨日、交貨方式、交貨地點或取貨方式、收貨聯絡資訊及必要備註。要求交貨日與交貨方式必填；客戶自取時可不填交貨地點及收貨聯絡資訊。
- **已辨識客戶與商品**：具有已核准且啟用的客戶、有效公司料號、可使用的客戶料號對應，以及有效交易單位。
- **幣別範圍**：本次專題只接受 TWD。其他幣別不提供建立、修改、匯入、API 或分析功能。
- **SO 送審快照**：SO 送審時保存當下選用的料號對應、價格、稅率、付款條件、單位換算與交貨資料。主檔後續變更不得直接改寫既有快照。

## 客戶料號與價格

客戶料號對應與客戶價格是兩個不同概念：

- 客戶料號對應用來把客戶使用的料號連到公司內部料號。
- 客戶價格用來保存該對應關係下的未稅 TWD 單價、計價單位、生效日與失效日。

本次專題只保存單一單價，不處理階梯價格、折扣公式、合約量或多幣別。價格符合下列條件時稱為目前有效價格：

```text
覆核狀態＝已啟用
且 生效日≤基準日
且（失效日未填或失效日≥基準日）
```

- 價格失效時，系統顯示警示，但不阻擋建立 SO item line 或 SO 草稿。
- 完全缺少價格時，仍可保存待補資料的 SO 草稿，但送審前須補上單價。
- SO 送審時保存實際採用的單價、價格日期狀態及固定 5% 稅率，供主管辨識是否使用失效價格。
- 待核准期間若客戶、料號對應或公司料號已停用，SO 不得核准；其他主檔異動則提示主管依快照核准或退回重送。

## 商品單位換算

每個商品須設定一個庫存基準單位，並可設定允許的銷售單位、採購單位、常用別名及換算倍率。例如庫存以米為基準，可設定 `1 捲＝20 米`。

SO、PO 與庫存異動須保存：

- 使用者輸入數量與單位。
- 交易當下的換算倍率。
- 換算後的基準數量。

庫存預留、入庫、出庫及可用量全部以基準數量計算。主檔換算倍率修改後，不回頭改寫既有交易。

## 庫存狀態桶

本次專題採互斥的狀態桶模型：

- `AVAILABLE`：一般可用，可被 SO 預留。
- `RESERVED`：已預留給特定 SO，尚未實際出庫。
- `QUARANTINED`：待檢、隔離、驗收不合格或主管暫停出貨。
- `DAMAGED`：已確認損壞，不可出貨。

```text
實際在庫
＝AVAILABLE
＋RESERVED
＋QUARANTINED
＋DAMAGED

可用庫存＝AVAILABLE
```

狀態桶為互斥數量，同一單位庫存同一時間只能屬於一種狀態，因此不可再從 `AVAILABLE` 重複扣除預留或不可出貨量。

- SO 核准時，系統依需求把數量由 `AVAILABLE` 轉為 `RESERVED`。
- 只有符合 DO 的 `RESERVED` 數量能完成出貨。
- DO 過帳時，對應 `RESERVED` 數量移出實際在庫。
- SO 取消核准後，未使用的 `RESERVED` 轉回 `AVAILABLE`。
- 入庫驗收的合格數量進入 `AVAILABLE` 或依關聯 PO 直接進入 `RESERVED`；待檢與不合格數量進入 `QUARANTINED`，損壞數量進入 `DAMAGED`。
- 隔離、解除隔離與庫存調整由具權限人員處理，全部保存商品、數量、原因、操作者及時間。

## SO 缺料與 PO 供應數量

為避免把 PO 草稿誤認為供應商已接單，系統分開呈現：

- **已規劃供應量**：來自未取消的關聯 PO 草稿、待核准、退回待修改、已核准及部分收貨數量，用來避免同一缺料重複建立 PO。
- **採購在途量**：只計入已核准或部分收貨，且尚未合格入庫或取消的 PO 數量。
- **尚待規劃供應量**：仍未預留、且尚未被任何未取消關聯 PO 涵蓋的需求。

```text
SO 未預留需求
＝有效訂購基準數量－已出貨基準數量－已預留基準數量

尚待規劃供應量
＝SO 未預留需求－未取消關聯 PO 所涵蓋的未完成數量

採購在途量
＝已核准採購量－合格入庫量－已取消量
```

只有尚待規劃供應量大於 0 時，才能再由 SO 一鍵建立關聯 PO 草稿。PO 草稿及待核准 PO 顯示為「已規劃、未下單」；核准後才顯示為「採購在途」。

關聯 PO 取消，或短收後明確結案時，未補足量重新成為尚待規劃供應量。一般補庫 PO 不綁定 SO，其合格入庫量全部進入 `AVAILABLE`。

一般補庫入庫、其他 SO 取消釋放、庫存調增或解除隔離增加的 `AVAILABLE`，本次專題不自動也不手動改配給既有缺料 SO。


## DO 與出貨規則

- SO 已核准且本次出貨量都在 `RESERVED` 時，業務才能釋出 DO。
- 產生正式 DO PDF 不等於出庫；倉管交付司機並執行過帳才移出庫存。
- 系統分別保存預計出貨日、實際出貨日及操作時間。
- 正式 PDF 作廢及重新產生須保留版本與操作紀錄。
- 同一 DO 只能成功過帳一次。
- 一張 SO 可對應多張 DO；每張已過帳 DO 各自產生一筆應收。

## 簡化財務與應收

本次專題付款條件：

```text
DUE_0 到期日＝DO 實際出貨日
NET_30 到期日＝DO 實際出貨日＋30 個日曆日
NET_60 到期日＝DO 實際出貨日＋60 個日曆日
```

`DUE_0` 只表示到期日等於實際出貨日，不進行出貨前收款檢查，也不阻擋 DO 過帳。

應收金額：

```text
未稅小計＝Σ（DO 實際出貨數量×SO 未稅單價快照）
營業稅＝未稅小計×5%
應收含稅總額＝未稅小計＋營業稅
```

本次交付的 TWD 文件總額與稅額在文件層級四捨五入至整數元。DO 過帳、應收草稿、正式應收與儀表板使用同一套後端金額計算結果。

應收狀態包含：

- `PENDING_CONFIRMATION`：DO 過帳後自動建立，待財務確認。
- `OPEN`：財務核對並填入外部發票資料後確認。
- `PARTIALLY_PAID`：已有部分收款，但未收餘額仍大於 0。
- `PAID`：未收餘額為 0。

```text
0＜本次核銷金額≤未收餘額

未收餘額
＝正式應收含稅金額－已核銷收款金額
```

`OVERDUE` 是動態標記：到期日早於今日且未收餘額大於 0。即將到期採閉區間：`今日≤到期日≤今日＋7 天`，包含第 7 天。

本次專題暫不處理預收、月底彙整請款、多張 DO 合併應收、退貨、折讓、退款、溢收、呆帳、跨客戶沖帳、多幣別、正式會計分錄、應付帳款及供應商付款。
