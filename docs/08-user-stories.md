# 核心 User Story

> 需求版本：v1.0  
> 建立日期：2026-09-29  
> 文件定位：保存本次專題的核心 User Story

| 編號 | 角色 | User Story |
| --- | --- | --- |
| US-01 | 業務 | 身為業務，我希望建立或查用公司料號，並建立客戶料號與對應關係，以便日後正確建立訂單。 |
| US-02 | 業務主管 | 身為業務主管，我希望覆核或退回公司料號、客戶料號、對應關係及價格，以便只讓確認過的資料投入交易。 |
| US-03 | 業務 | 身為業務，我希望建立含有價格缺漏或失效警示的 SO 草稿，並在送審時保存實際採用的價格及交易快照，以便辨識例外且避免主檔異動改寫交易。 |
| US-04 | 業務主管 | 身為業務主管，我希望 SO 核准後才預留庫存並開放缺料採購與出貨，以免未成立需求占用庫存或提前採購。 |
| US-05 | 採購 | 身為採購，我希望把已核准 SO 尚待規劃的缺料建立為關聯 PO 草稿，或依安全庫存建立一般補庫 PO，以便處理訂單需求與日常補貨。 |
| US-06 | 採購主管 | 身為採購主管，我希望 PO 核准後才產生正式 PDF、形成採購在途並向供應商下單，以便控管採購承諾。 |
| US-07 | 倉管 | 身為倉管，我希望依 PO 記錄合格、待檢、不合格與損壞數量，以便庫存進入正確狀態，且關聯 PO 的合格數量能補足來源 SO。 |
| US-08 | 業務 | 身為業務，我希望在 SO 已核准且本次出貨量均已預留後釋出 DO，以便倉管依交貨安排履約。 |
| US-09 | 倉管 | 身為倉管，我希望依 DO 完成揀貨、包裝、實際數量確認及正式出貨單 PDF，以確保貨物與文件一致。 |
| US-10 | 倉管 | 身為倉管，我希望在貨物與文件交給司機時執行出貨過帳，以便正式移出庫存、鎖定 DO 並留下操作紀錄。 |
| US-11 | 財務 | 身為財務，我希望核對每張已過帳 DO 自動產生的應收草稿，填入外部發票資料並確認正式應收，以便追蹤收款且避免重複請款。 |
| US-12 | 業務 | 身為業務，我希望申請取消尚未出貨的剩餘數量，以便主管核准後釋放預留，並把取消金額計入實際核准期間。 |
| US-13 | 系統管理員 | 身為系統管理員，我希望替其他員工指派多個角色或個別權限並保留紀錄，同時禁止任何人修改自己的授權，以因應兼任及擴編並降低自行提升權限的風險。 |
| US-14 | 業務 | 身為具權限的業務，我希望完成本人 LINE 綁定，用自然語言輸入需求，依 AI 提示補充資料並確認 Structured Output 後建立 SO 草稿，以減少人工輸入又保有最後確認。 |
| US-15 | 營運主管 | 身為營運主管，我希望比較接單與已過帳銷售趨勢，並依客戶、商品及訂單狀態查看變化來源，以便決定優先處理的營運問題。 |
| US-16 | 營運主管／採購主管 | 身為主管，我希望查看缺貨風險，以及其 `AVAILABLE`、已預留、已規劃供應、採購在途、SO 與 PO 依據，以便決定催辦採購、協調交期或分批出貨。 |
| US-17 | 業務主管 | 身為業務主管，我希望查看交易降溫客戶及其歷史交易變化，以便安排業務確認原因與後續聯繫。 |
| US-18 | 營運主管 | 身為營運主管，我希望取得附有來源資料的 AI 營運摘要，以便快速掌握重要異常、可能原因及建議處理順序。 |
| US-19 | 財務 | 身為財務，我希望系統依 `DUE_0`、`NET_30` 或 `NET_60`，以 DO 實際出貨日計算到期日，以便用一致規則管理應收。 |
| US-20 | 業務／採購／倉管 | 身為交易承辦人，我希望系統把銷售或採購單位換算成庫存基準單位，以便入庫、預留與出庫數量保持一致。 |
| US-21 | 營運主管 | 身為營運主管，我希望在原核准人本身就是申請者時，以相應權限替代核准客戶、SO、供應商、PO 或付款條件，以落實建立者不得核准自己的規則。 |
| US-22 | 財務主管 | 身為財務主管，我希望核准或退回客戶的 `NET_30` 或 `NET_60` 申請，以便授信條件不由業務部門單獨決定。 |
| US-23 | 採購 | 身為採購，我希望區分 SO 缺料中哪些已有 PO 規劃、哪些已成為正式在途、哪些仍無供應來源，以便避免重複採購並正確追蹤供應進度。 |

## 後續補充欄位

每則 User Story 後續應補充：

- 對應痛點與產品目標。
- 交付優先級。
- 前置條件與相依 Story。
- Given／When／Then 驗收條件。
- 權限與資料範圍。
- 例外及錯誤處理。
