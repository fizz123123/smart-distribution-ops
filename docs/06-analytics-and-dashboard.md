# 營運分析與儀表板需求

> 文件版本：v1.0  
> 建立日期：2026-09-29  
> 最後更新：2026-11-23  
> 文件定位：定義本次專題交付範圍內的儀表板問題、指標口徑、分析規則、下鑽與驗收方式。

## 分析目的

儀表板的目的不是堆疊圖表，而是協助管理者針對以下問題採取行動：

1. 本期接單或營收為何上升或下降？
2. 哪些訂單與商品有缺貨或延遲風險？
3. 哪些客戶的交易行為正在降溫？
4. 有多少應收尚未收回、即將到期或已逾期？
5. 哪些核准、採購、入出庫或財務事項需要優先處理？

每項指標須有固定口徑、資料期間、權限範圍及來源連結。

本次專題只交付四組核心資訊：接單與營收、缺貨與採購、客戶交易降溫、應收與逾期。指標由交易資料即時計算並提供來源下鑽，不建立永久指標快照表、排程彙總、自訂報表工具或機器學習預測。

## 期間與金額口徑

- 儀表板預設本期為本月 1 日到今日，前期為上個月 1 日到同一天；上個月沒有那一天時到月底（D-083）。
- 本期為使用者選擇的日期區間，最長 366 天。
- 自訂期間剛好是整月時，前期為前面相同個數的整月；其他自訂期間的前期為緊接本期之前、長度相同的日期區間。
- 近六個月趨勢固定為今日所在月份往前共六個自然月，不隨期間改變；本月標示為截至今日的累計。
- 接單、營收與客戶／商品貢獻一律採未稅 TWD。
- 含稅金額只用於應收與收款，不與未稅營運指標混合彙總。
- 本次不計算已付款成本、實際現金支出、會計毛利或應付餘額。如畫面顯示 PO 採購單價或採購金額，其來源為已核准 PO，不得標示為已付款或會計成本。

本專題將「營收」定義為統計期間內已過帳 DO 的實際出貨未稅金額，並以 DO 的實際出貨日歸屬期間（D-084）。金額直接加總應收明細的未稅小計：DO 過帳時應收明細已用實際出貨量與 SO 未稅單價快照建立（D-076），所以營收和應收一致。這是本系統用於營運分析的營收口徑，不代表已串接會計總帳或完成法定收入認列；SO 核准、應收確認及收款日期均不作為營收歸屬日期。

## 營運總覽

首頁以管理者能快速判斷及採取行動為原則，呈現：

- 六張核心指標卡：「本期」營收與淨接單額，以及「截至今日」的已接單未出貨金額（副標：其中已逾交期的金額）、缺料影響金額（副標：涉及的料號數，D-086）、交易降溫客戶數（副標：其中高風險人數）及逾期應收金額（副標：筆數與其中未確認筆數）。
- 一張近六個月趨勢圖：並列淨接單額與營收，避免將接單與實際履約混為同一指標。
- 三張待處理清單：缺貨與履約風險（依最早交期）、交易降溫客戶（只列高、中風險，依等級與平均月營收）、即將到期與逾期應收（依到期日）；各取前 10 筆並附總筆數。
- 四個分析詳情入口：接單與營收、缺貨與採購、客戶交易降溫、應收與逾期。

新增核准 SO 數、核准取消額、平均新增訂單金額、活躍客戶數、下單客戶數、準時交貨率、未出貨的供應狀態拆解、應收總額、未收餘額、待確認應收、應收帳齡與供應商表現，放在對應詳情頁呈現，不堆疊於首頁（D-089）。總覽只回答「現在哪裡有問題」；首頁的每個數字都直接取自對應詳情，所以總覽和詳情一定相同。

營運總覽只有營運主管能看；其他角色打開儀表板時，只顯示其權限看得到的詳情（D-085）。

儀表板的三張待處理清單是跨部門營運風險，不取代個人作業待辦。待核准、待處理及近期操作由 HOME-01「我的工作台」承接；儀表板可以顯示「我的待辦」入口或數量並連至該畫面，但不另建立「待辦中心」。AI 摘要只協助排列營運問題的處理優先順序，也不是查看或執行待辦的唯一入口。

期間型指標會隨日期篩選改變；已接單未出貨、缺貨風險、未收、到期、逾期及三張待處理清單呈現查詢當下狀態，不受一般期間篩選影響，也不代表系統保存永久快照。交易降溫依所選分析基準日 `asOf` 計算，預設為今日，可以指定過去的日期但不能是未來；首頁一律以今日為準。其他狀態型指標沒有歷史快照，不提供過去的基準日（D-083）。

首頁、趨勢圖、待處理清單及四個分析詳情的指標，均須能依權限下鑽至形成結果的客戶、商品或來源單據。

## 接單與營收指標

```text
本期新增核准 SO 數
＝本期首次核准的 SO 張數

本期新增核准接單額
＝本期首次核准 SO 的明細未稅小計加總

平均新增訂單金額
＝本期新增核准接單額÷本期新增核准 SO 數

淨接單變動
＝本期新增核准接單額－本期核准取消額

本期核准取消額
＝本期核准的取消申請明細之（取消數量×SO 明細未稅單價）加總，四捨五入到分

本期營收
＝實際出貨日在本期的應收明細未稅小計加總
＝本期所有已過帳 DO 明細之（實際出貨數量×SO 未稅價格快照）加總

準時交貨率
＝實際出貨日在本期、實際出貨日不晚於 SO 明細交期的已過帳 DO 明細筆數÷本期已過帳 DO 明細筆數
```

- 接單額用明細小計加總，不用表頭四捨五入到元的金額，客戶與商品拆解才加得回總數；兩者每張 SO 相差不超過 0.5 元（D-084）。
- 核准取消額依取消實際核准期間計算，不回溯改寫原 SO 核准月份。
- 平均新增訂單金額不以淨接單變動計算。
- 活躍客戶為本期至少有一張 DO 過帳的客戶。
- 下單客戶為本期至少有一張 SO 首次核准的客戶。
- 已接單未出貨金額是即時存量，以有效訂購數量扣除已出貨及已核准取消數量計算；其中交期早於今日的部分另列為逾期未出貨。
- 本期沒有出貨時，準時交貨率不計算並標示資料不足。
- 依商品篩選時，SO 數是含該商品的 SO 張數，接單額、取消額與未出貨只算該商品的明細。
- 只有已過帳（`POSTED`）的 DO 納入營收；草稿、待交車（`READY`）及作廢 DO 不納入。
- 本次專題不處理退貨與銷貨折讓，列為後續擴充。
- 前期金額為 0 時只顯示絕對變化及「前期無比較基準」，不計算百分比。

## 接單與營收變化分析

至少提供：

- 近六個月新增核准接單額、取消額、淨接單變動與營收趨勢。
- 本期與前期的訂單數、平均訂單金額及活躍客戶數比較。
- 依客戶與商品拆解的營收增減貢獻排行。
- 已接單未出貨金額與供應狀態，用來區分接單變化與尚未完成履約的訂單。

計算基準：

```text
營收變化額
＝本期營收－前期營收

營收變化率
＝營收變化額÷前期營收（僅在前期營收大於 0 時計算）

某客戶或商品的營收貢獻變化
＝該客戶或商品本期營收－前期營收
```

- 後端分別列出營收減少最多及增加最多的前三名客戶與商品，並提供金額、變化額及來源明細。
- 不跨商品計算「全公司平均出貨單價」。各商品的單位不同，整體平均單價不具決策意義。
- 若需要判讀數量或價格變化，只能在同一公司料號內，以一致的基準單位比較；跨商品分析一律使用營收貢獻金額。
- 未出貨訂單依供應狀態拆解（見「缺貨風險分析」的六種狀態）；每筆明細只歸一個狀態，各狀態金額加總等於未出貨總額。不因同時出現缺料或在途資料就直接判定其造成營收下降（D-086）。
- 缺料影響金額＝供應狀態為「缺料待處理」或「採購延遲風險」的未出貨金額，用於首頁卡片。
- 系統及 AI 只能將客戶、商品、取消與未出貨狀態描述為「可能原因」或「相關變化」，不得在沒有直接證據時宣稱因果關係。

管理者可由結果決定是否聯繫交易下降的主要客戶、處理缺料、檢視商品需求或調整經營優先順序。

## 應收分析

- 應收總額只包含 `OPEN`、`PARTIALLY_PAID` 與 `PAID` 的正式含稅應收，不包含 `PENDING_CONFIRMATION` 或已作廢資料。
- 未收餘額為正式應收含稅金額扣除已核銷收款。
- `PENDING_CONFIRMATION` 另以待確認筆數及含稅金額呈現。
- 即將到期為未收餘額大於 0 且 `今日≤到期日≤今日＋7 天`。
- 逾期為未收餘額大於 0 且到期日早於今日。
- 即將到期與逾期包含尚未確認的應收草稿，並另列其中未確認的筆數，和應收清單的判斷一致（D-081）。
- 帳齡依逾期天數將未收餘額分為：未到期、逾期 1～30 天、31～60 天、61～90 天、91 天以上；逾期四組加總等於逾期金額（D-089）。

## 缺貨風險分析

本次專題使用可說明依據的規則，不使用機器學習預測。清單至少整合：

- 商品。
- 可出貨實體數量、有效預留數量與可用庫存。
- SO 未預留需求及尚待規劃供應量。
- PO 已規劃未下單量與正式採購在途量。
- PO 預計到貨日與客戶要求交貨日。
- 最近 30 天平均日出貨量、可支撐天數、平均採購週期與建議再訂購點。

計算基準：

```text
近 30 天平均日出貨量
＝最近 30 個日曆日已過帳 DO 基準數量加總÷30

可支撐天數
＝可用庫存÷近 30 天平均日出貨量

平均採購週期
＝最近六個月狀態為 `COMPLETED` 且具有合格收貨的 PO 明細，自 PO 核准日至完成合格收貨日的日曆日平均

建議再訂購點
＝近 30 天平均日出貨量×平均採購週期
```

「平均日出貨量×採購週期」算的是從下單到貨這段時間預期會用掉的量，也就是再訂購點；安全庫存是應付需求波動額外多放的量，兩者不同，所以不稱為「建議安全庫存」（D-087）。

- 近 30 天為今日往前 29 天到今日，共 30 個日曆日。
- 平均日出貨量為 0 時，可支撐天數顯示「無近期耗用」，不進行除法；可支撐天數無條件捨去到小數 1 位，不高估。
- 平均採購週期以最後一次合格收貨日判斷是否在最近六個月內；沒有完整 PO 歷史時，平均採購週期與建議再訂購點顯示資料不足。
- `CANCELLED` 與 `CLOSED_SHORT` 明細不納入平均採購週期，避免未完整履約或零收貨資料扭曲結果。
- 建議再訂購點以近 30 天出貨量直接計算，不使用四捨五入後的日出貨量，並向上取整至庫存基準單位允許的小數位；只作為決策參考，不自動修改由採購主管維護的商品安全庫存設定。
- 缺貨分析不回傳售價與 PO 採購單價，採購與倉管也能查看。

符合下列任一條件時標示風險，清單只列至少有一項風險的商品，依受影響 SO 明細中最早的交期排序：

| 分組 | 代碼 | 條件 |
| --- | --- | --- |
| 庫存面 | `BELOW_SAFETY_STOCK` | 可用庫存低於安全庫存 |
| 庫存面 | `BELOW_REORDER_POINT` | 可用庫存加採購在途低於建議再訂購點 |
| 供應面 | `UNPLANNED_DEMAND` | 已核准 SO 仍有尚待規劃供應量 |
| 供應面 | `PO_NOT_APPROVED` | SO 缺料只有 PO 草稿或待核准 PO，尚未形成正式採購在途 |
| 供應面 | `ARRIVAL_AFTER_DELIVERY` | 關聯的已核准 PO 預計到貨日晚於 SO 明細交期 |
| 供應面 | `ARRIVAL_OVERDUE` | 已核准 PO 已超過預計到貨日但尚未完成合格入庫，含一般補庫 PO |

庫存面只判斷啟用中的商品；供應面不論商品是否停用都判斷，因為那是已經接下的訂單（D-087）。

管理者可由清單建立或催辦 PO、催促供應商、協調交期或評估分批出貨。只有安全庫存不足、沒有 SO 缺料時，可建立一般補庫 PO 草稿。本次專題不自動決定採購量、不自動送審或下單。

每筆已核准 SO 明細的供應狀態依下表由上往下判斷，只歸一個狀態（D-086）：

| 狀態 | 條件 |
| --- | --- |
| 缺料待處理 | 尚待規劃 > 0 |
| 採購延遲風險 | 關聯的已核准 PO 還沒收齊，而且預計到貨日晚於交期，或已經過了預計到貨日 |
| 已規劃、未下單 | 已規劃未下單 > 0 |
| 部分到貨 | 關聯的 PO 已有收貨、仍有在途 |
| 採購在途 | 採購在途 > 0 |
| 已備齊 | 以上都不是，剩餘需求都已預留 |

前三種狀態的 SO 明細列為商品的「受影響 SO 明細」。

## 供應商表現

缺料的根本原因常是供應商不準時。缺貨與採購詳情另列最近六個月的供應商表現，不含價格（D-089）：

| 指標 | 計算方式 |
| --- | --- |
| 統計的 PO 明細 | 最近六個月結束的 PO 明細：`COMPLETED` 以最後一次合格收貨日、`CLOSED_SHORT` 以 PO 短收結案日判斷 |
| 準時到貨率 | `COMPLETED` 且最後一次合格收貨日不晚於 PO 預計到貨日的筆數÷統計筆數；短收結案一律算不準時 |
| 平均交期 | `COMPLETED` 明細從 PO 核准日到最後一次合格收貨日的天數平均，和平均採購週期同一個算法 |
| 收貨異常率 | 最近六個月的收貨明細中，有破損或不合格數量的筆數÷收貨明細筆數；不同商品單位不能加總，所以用筆數 |
| 目前逾期未到 | 已核准未結、預計到貨日早於今日的 PO 張數 |

- 列出最近六個月有結束的明細、有收貨，或目前有逾期 PO 的供應商；統計筆數少於 3 筆時，準時到貨率標示資料不足。
- 依準時到貨率由低到高排序，表現最差的在前。
- 依商品篩選時，只計算該商品的 PO 明細。

## 客戶交易降溫分析

工程材料 B2B 客戶常依工程進度不定期採購，因此本次專題只稱為「交易降溫風險」，不直接判定客戶流失。至少比較：

- 最後交易日期與距今天數。
- 歷史平均交易週期。
- 本期與前期新增核准的 SO 數量及金額（依核准日）。
- 本期與前期的營收（依實際出貨日）。
- 目前缺料中的 SO 明細數，以及本期的取消申請與延遲出貨紀錄。

交易日為已核准 SO 的訂單日期，同一天的多張 SO 只算一個交易日（D-088）。客戶至少須有 3 個不同的交易日，才計算歷史平均交易週期：

```text
歷史平均交易週期
＝（最後一個交易日－第一個交易日）÷（交易日數－1）
```

不足 3 個交易日時顯示「資料不足」，不評定風險。只計算分析基準日以前已核准、訂單日期也在基準日以前的 SO。

```text
距上次交易天數÷歷史平均交易週期 > 2.0：高風險
距上次交易天數÷歷史平均交易週期 > 1.5 且 ≤ 2.0：中風險
其餘：不列入交易降溫警示
```

- 比值取到小數 2 位後判斷等級，畫面看到的比值和等級一致。
- 停用的客戶照算比值，但不評定風險等級。
- 業務只查看自己負責的 SO 時，交易週期也只用自己負責的 SO 計算。
- 清單依等級（高、中、未達警示、資料不足）排序，同一等級再依平均月營收（基準日往前六個月的營收÷6）由高到低。

補充證據沿用接單與營收分析的口徑，和該頁篩選同一客戶時的數字相同；只作為人工判讀依據，不自行改變上述風險等級。結果供業務確認及安排聯繫，不由系統自動判定客戶已流失或採取對外行動。

## 下鑽與權限

- 指標與警訊須能連回形成結果的客戶、商品、SO、PO、DO 或應收紀錄；營收、新增接單、核准取消與已接單未出貨另有來源明細清單，加總等於對應指標。
- MANAGER 可查看營運總覽與全公司結果。
- 採購與倉管依職務查看缺貨、補貨、供應商表現及履約資訊，但不因此取得非必要價格或成本。
- 業務主管查看全部業務的接單營收與交易降溫，以及缺貨分析；一般業務只查看自己負責的 SO。
- 財務查看應收與逾期。
- 各區塊的權限代碼見 D-085。
- 所有明細仍受 [04-roles-and-permissions.md](04-roles-and-permissions.md) 約束。

## 分析驗收原則

- 相同期間與條件下，指標卡、圖表、下鑽明細及 AI 摘要使用一致結果。
- 管理者可從警訊回到來源紀錄驗證原因。
- 使用者只能取得其權限範圍內的統計與明細。
- 資料不足時明確顯示，不以 AI 補造結論。
- 展示資料使用匿名化匯入資料或合理模擬資料，讓趨勢、風險與結果可被重現。

展示資料須涵蓋前後期營收變化、至少一項缺貨風險、一名交易降溫客戶及一筆逾期應收，並能重現相同計算結果。
